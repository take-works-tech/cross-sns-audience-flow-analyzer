# Screens, transitions and shared components

The inventory of what the user sees and how they move between those places. Written once, at project
level, because a screen invented per feature is how the same concept gains a second implementation.
Screen content follows v1.0 §5.2 and §16 (E-001); the visual language follows the "calm instrument"
design-system decision in [08_decisions.md](08_decisions.md).

## Screens

| Screen | Purpose | Entered from | Leaves to | Empty state | Error state |
|---|---|---|---|---|---|
| Initial (v1.0 §16.1) | Entry hub: create a @Project, open a recent one, try the sample dataset (OPEN-003), start a @Platform connection, URL input guidance | App root after login | Main analysis; Settings | First run is the designed state: the four primary actions replace the recents list | Project-list load failure shows the reason inline with a retry; the four actions stay usable |
| Main analysis (v1.0 §16.2) | Three-pane workspace where all analysis happens; top bar holds @Period, filters, save state, and @Recalculation status | Initial (open or create); Settings (back) | Settings; Initial (project switcher) | Empty @Canvas states the two starting moves: paste a URL, or drag from the @Unplaced node list; each pane has its own designed empty state | Last computed graph stays rendered with a stale marker and a stated reason (INV-005); a failed @Recalculation keeps the previous edges (flow-analysis/REQ-003) |
| Settings (v1.0 §16.4) | @Connection management, project defaults (thresholds), display theme, animation intensity | Initial; Main analysis | Back to the caller | No connections: connect actions per @Platform with the capability label (@Observed flow or @Estimated flow only) visible before connecting | OAuth denial or failure shows the platform's reason and records no @Connection (sns-connection/REQ-001) |

**Empty and error states are columns, not afterthoughts.** They are the states a user meets first and
most often. Every error text carries a `domain.reason` message ID from
[03_failure_policy.md](03_failure_policy.md) and names the limit or cause that refused the action.

### Primary flow (v1.0 §17.1)

Login, connect an account, create a @Project, paste a URL, drag the generated @Node onto the
@Canvas, watch edges and the @Flow animation appear, tune thresholds and edges, read the detail
panel, save. The felt experience target: touching the inflow structure, not operating an analysis
tool.

## Three-pane layout (v1.0 §5.2)

| Pane | Holds | Backing feature |
|---|---|---|
| Top bar | @Period selector, display filters, save state, @Recalculation status and manual trigger | projects/REQ-002, flow-analysis/REQ-003 |
| Left pane | @Connection list, URL input, @Unplaced node list with search and @Node kind sort, filter templates | sns-connection/REQ-001, url-nodes/REQ-003 |
| Center pane | The @Canvas: graph, node placement, edges, @Flow animation, zoom, pan, multi-select, minimal toolbar | canvas/REQ-001, edges/REQ-001 |
| Right pane | Detail and analysis panel: selected @Node or @Edge, inflow count and rate, @Confidence, @Metric series chart, recalculation info, per-edge settings | detail-panel/REQ-001, detail-panel/REQ-002 |

Below LIM-019 the side panes collapse into drawers and the @Canvas keeps the full width
(canvas/REQ-005). The center pane is never sacrificed to either side pane.

## State transitions

| State | Entered when | What stays usable | Exits when |
|---|---|---|---|
| Loading | A @Project opens; each pane shows its designed skeleton | Top bar navigation | Interactive @Canvas within LIM-005 (canvas/REQ-003) |
| Ready | Load or any background job completes | Everything | Any trigger below |
| Recalculating | A trigger fires after the LIM-009 debounce | Full canvas interaction; previous edges stay rendered under a progress indicator | Job completes or fails (flow-analysis/REQ-003) |
| Saving | A change passes the LIM-008 autosave debounce | Everything; indicator shows saving, saved, or unsaved with retry | Save succeeds or fails (projects/REQ-002) |
| Degraded | Frame rate stays below LIM-004 | Everything; @Particle quality steps down first, interaction handling last | Frame rate recovers, one quality step at a time (flow-animation/REQ-002) |
| Stale | A @Recalculation fails or an external API fails | Everything; graph kept with stale marker and stated reason | Next successful @Recalculation (INV-005) |

### XC-060 - Transition and interruption rules
- statement: recalculation, autosave, and @Metadata fetch run in the background and never lock the @Canvas; modal dialogs are reserved for destructive confirmations (delete project, disconnect); a newer trigger supersedes a queued @Recalculation inside the LIM-009 debounce; while an export runs, only its own control is disabled
- judged_by: XC-003, XC-004
- decidedness: Bounded

## Node visual taxonomy (v1.0 §4.3)

### XC-061 - Node kind visual taxonomy
- statement: every @Node renders as a rounded card or circular badge whose @Node kind is readable from icon, shape, and label alone; labels stay short; per-kind detail lives in the right pane, never crammed into the node
- decidedness: Fixed
- basis: E-001 (T1)

#### Per-kind appearance

| @Node kind | Base | Shows | Non-color distinguishers |
|---|---|---|---|
| SNS account | Large rounded card, platform brand tint | Platform icon, account name, follower or subscriber count | Largest size; circular platform badge |
| SNS post | Medium card | Thumbnail or simplified visual, title or leading text, condensed date and view count | Thumbnail-led medium card |
| Video | Medium card, thumbnail emphasized | Thumbnail with play glyph, title | Play glyph |
| Generic URL | Uniform rectangular card | Domain plus page title | Globe glyph; no thumbnail emphasis |
| Product page | Extended card | Small price and product image | Price-tag glyph |
| Site top | Rectangular card, domain-primary | Domain as title; treated as the whole-site entry point | Home glyph |

Platform brand color appears only as node identity, with text contrast at or above LIM-017
(canvas/REQ-002). A missing thumbnail falls back to the kind icon plus domain label, never a broken
image.

## Design tokens and themes

### XC-062 - Token architecture and themes
- statement: every color, radius, spacing step, and duration is a CSS-variable design token consumed through Tailwind's `@theme` layer (E-019 (T2)); components reference tokens only, never raw values; the three themes - dark (default), light, high contrast - differ only in token values, and each keeps text contrast at or above LIM-017 (E-007 (T1))
- decidedness: Bounded

#### Token set

- Neutrals: cool zinc ramp for surfaces, borders, and text.
- Accent: one cyan accent, reserved for interactive elements and @Observed flow. Nothing else is cyan.
- @Estimated flow: dashed and desaturated, distinguished from @Observed flow by at least two non-color channels (INV-003).
- Spacing: 4px grid.
- Radii: 8px cards, 6px controls.
- Depth: 1px borders, not shadows.
- Icons: lucide only.
- Type: Geist plus Noto Sans JP; every numeral tabular so columns of counts align.
- Motion: micro-transitions per LIM-018, ease-out; the @Flow animation is the only continuous animation; prefers-reduced-motion replaces it with static directional encoding (flow-animation/REQ-003, E-008 (T1)).

### XC-063 - Forbidden styling
- statement: a screen containing any entry of the forbidden list fails design review; the product reads as a calm instrument, not a landing page
- decidedness: Bounded

#### Forbidden list

- Purple-pink gradients.
- Glassmorphism and frosted-glass panels.
- Emoji in UI copy.
- Marketing-hero layouts.
- Decorative shadows.
- Color as the only encoding of any meaning (INV-003).

## Shared components

Named here so the same concept does not gain a second implementation later. A component listed here
has one implementation, and a feature that needs something similar either uses it or explains why it
is genuinely different.

|---|---|---|---|
| NodeCard (one variant per @Node kind) | The XC-061 taxonomy, identical on canvas and in lists | MOD-001 | Canvas, unplaced list, detail-panel header |
| EdgePath | edges/REQ-004 encoding: thickness, opacity, arrowhead, dash pattern | MOD-001 | Canvas |
| ParticleOverlay | @Flow animation on a canvas layer following React Flow edge paths (E-009 (T2)), capped at LIM-016 | MOD-001 | Canvas |
| FlowTypeTag | Labels @Observed flow versus @Estimated flow wherever a flow value appears | MOD-001 | Edge hover, detail panel, connection list |
| ConfidenceBadge | @Confidence as a number, echoed by opacity | MOD-001 | Edge hover, detail panel |
| PeriodPicker | The single control that sets a @Period | MOD-001 | Top bar, period comparison |
| ThresholdControls | Count, rate, and @Confidence thresholds (default LIM-013) | MOD-001 | Top bar, per-edge settings |
| SaveStateIndicator | Saved, saving, or unsaved with retry (projects/REQ-002) | MOD-001 | Top bar |
| RecalcStatus | Progress and stale marker (flow-analysis/REQ-003) | MOD-001 | Top bar, detail panel |

| ConnectionCard | @Platform, account name, status, capability label | MOD-001 | Settings, left pane |

## Conventions

- Layout and spacing: three panes plus top bar on the 4px grid; side panes collapse to drawers below LIM-019; the @Canvas never scrolls the page, it pans.
- Typography and colour: the XC-062 token set; text contrast at or above LIM-017 in all three themes; numbers right-align in tables and tick up or down with a brief transition per LIM-018 rather than swapping.
- Interaction: full keyboard operability with visible focus (accessibility items in [07_cross_cutting.md](07_cross_cutting.md)); Delete removes the selected @Edge (edges/REQ-002); Escape closes transient surfaces; canvas edits are undoable within the session; every refusal names the limit or reason that caused it (XC-005).

These belong here rather than in a feature spec: written per feature, they diverge, and the
divergence is visible to the user as an interface that feels assembled by different people.
